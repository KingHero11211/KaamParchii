# KaamParchi demo

## Setup

Use fictional customer details and one saved sample job. The original instructions must include preserving data, a ₹600 spending limit, and permission before replacing parts. Prepare the microphone and both API keys. Phone calling is awaiting separate access, so show the working in-app workflow.

Record the complete interaction first. For the 60-second edit, shorten processing waits and label shortened waits on screen. Keep actual model results and customer corrections visible. Have a saved sample job available for rehearsing the technician section.

## Rehearsal checks

- Corrected price remains ₹600 in the original intake.
- ₹950, part replacement and reset trigger visible concerns with supporting words.
- A free visual inspection with no reset, no replacement and permission before paid work produces no conflicts in the sampled check.
- Replacing the initial ₹950 estimate with an explicit final ₹550 estimate uses the correction.
- Missing price prompts clarification.
- Customer permission for a board replacement does not automatically remove the recorded data restriction or authorise reset.
- Rechecking preserves the exact question that the recorded answer addressed.
- Editing or removing the transcript clears earlier findings and generated reminder audio.
- A compatible plan receives a neutral spoken reminder.

## Submission description

KaamParchi is a voice-assisted repair handover app for small phone repair shops. Gnani Prisma captures mixed Hindi and English speech. The shop reviews the extracted details and confirms the intake. At the workbench, a technician speaks the proposed repair, and the app compares it with the customer's recorded instructions, spending limit and approval requirements. Findings include source quotes, while Gnani Timbre speaks a reminder. A clarification loop records the customer's answer alongside the question for further review.

Gemini supplies structured extraction and possible conflict analysis. Application code validates source quotes and compares the extracted estimate with the spending limit. The prototype requires human review and currently keeps intake jobs in browser storage. Outbound phone integration awaits Agent Builder access and is excluded from this working-flow demonstration.
